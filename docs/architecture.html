dynamic_react core + 세트 레이어 선로도 모드 run 제어·이벤트 저장 모델 호출 신호표

core 는 빈 칸 22개짜리 틀이다. 세트를 끼워야 돈다

core 는 step 의 순서와 신호 규칙만 가진다. 칸 안에서 할 일은 하나도 모른다. 일은 세트(inject.FunctionSet)가 한다. 세트는 22칸 중 자기가 맡을 칸에만 함수가 있는 카드이고, inject.Bind 가 카드를 겹쳐 core 에 끼운다. 단계를 눌러 카드를 하나씩 끼워 보고, "모드 전환 재생"으로 실행 중에 카드 묶음이 바뀌는 순간을 보라.

core 가 부르는 함수 (맨 위) ctx.Next() 로 이어서 불림 가려짐 빈 동작 (칸만 채움) 등록만 됨 (끼우지 않음) 빈 칸 → Bind 거부

카드 한 장 = FunctionSet 하나

inject.FunctionSet{
  Name: "guard",
  ToolBefore: func(ctx, call) {
    if bad(call) { return 차단 }
    return ctx.Next(call) // 아래 카드로
  },
  // 나머지 21개 칸은 nil
}

카드의 이빨은 nil 이 아닌 칸이다. guard 는 16번 칸에만 이빨이 있다.

      카드는 모델을 어떻게 부르나
      
  
      모델을 부르는 일도 칸 몇 개에 나뉘어 있다. 6·7번에서 요청을 만들고, 8번에서 모델을 고르고, 9번에서 보낸다. 답은 10·11·12번으로 돌아온다. 판단기 같은 단발 호출은 칸을 거치지 않고 같은 통로를 쓴다. 상자를 누르면 설명이 나온다.

      카드 함수는 core 에 어떻게 지시하나
      
  
      카드 함수는 결과와 함께 신호 배열을 돌려준다. core 는 그 신호만 보고 다음 칸을 정한다. 신호는 13종이고, 칸마다 쓸 수 있는 신호가 정해져 있다. 허용되지 않은 신호는 그 칸의 ctx 에 메서드가 없어서 컴파일되지 않는다. 신호를 골라 보라.
      
  
      
    
      
      
      
      
      
      
      
      전체 신호표 펼치기
      
    
      
    
      
      
      배열 규칙
      
      
      return []Signal{
  ctx.Rewrite(edit),   // 효과: 0개 이상
  ctx.InjectInput(msg),
  ctx.ContinueTurn(),  // 전이: 최대 1개, 맨 뒤
}
      
      
      전이 신호가 없으면 next 다. 단 12번 call.error 와 20번 turn.finish 는 next 를 허용하지 않는다. 다음에 할 일을 함수가 꼭 밝혀야 하는 갈림길이기 때문이다.
      
      
      효과와 전이
      
      
      효과 신호는 상태에 작용하고 칸을 옮기지 않는다(편집 추가, 입력 넣기, 도구 선행 실행). 전이 신호는 다음 칸을 정한다. core 는 효과를 배열 순서대로 적용한 뒤 전이한다.
